claude-lcls names a token in ~/.claude when started from home

deploy-opencode PR #59 · 2026-11-20 · host sdfiana024 | binary 2.1.311 (Claude Code) | NEW md5 3f17628b | OLD md5 063ea7d6

A client's claude-lcls failed with 401 … Received=your****Here, but only when started in the home folder. Claude Code reads <launch folder>/.claude/settings.json as project settings, and CLAUDE_CONFIG_DIR does not move it. Started in home, that file is the personal ~/.claude/settings.json. His held a gateway setup for plain claude with a placeholder ANTHROPIC_AUTH_TOKEN on line 4. The launcher now names that file and line on stderr. It changes nothing else. 10/10 checks pass.

The warning, as printed by check A1

claude-lcls: ~/.claude/settings.json line 4 sets ANTHROPIC_AUTH_TOKEN. Started in your home folder, Claude Code reads that file as project settings and sends that token instead of your key from ~/.config/slac-ai/key.dat. Remove that entry, or start claude-lcls from another folder.

How it was tested

  • A fresh fake HOME under /tmp on sdfiana024, the shared binary 2.1.311, and a clean environment (env -i).
  • The key is fake: apiKeyHelper prints fake-helper-key-0001.
  • The published shared-settings.json with only the gateway URL swapped for a local listener. It answers 401 and logs the Authorization header, so each check sees which key Claude Code sent. Nothing reached the gateway.
  • The client's ~/.claude/settings.json is reproduced with the same keys and line numbers (token on line 4); the placeholder value is illustrative.

Not covered
